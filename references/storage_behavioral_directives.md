## Storage & behavioral directives

Writes MEMORY.md **only** via `scripts/memory_guard.py` (`--apply --file ~/.hermes/profiles/<profile>/memories/MEMORY.md`); Finch is the sole maintainer. **The built-in `memory` tool is a whole-file rewriter that keeps ONE entry — it is not an editor, and using it is a data-loss event, not a compaction.** Two independent barriers exist and neither may be assumed live: (a) the `pre_tool_call` hook in `agent-hooks/block-memory-tool.sh`, and (b) `memory.memory_enabled: false` in `config.yaml`. **The hook's firing is NOT verified** — a `memory` call with `target=memory` succeeded on 2026-09-29T17:08:51Z against both barriers (the hook did not fire and the flag was still true), so a registration in `config.yaml` is not evidence the gate works. Verify an invariant by ATTEMPTING the forbidden action, not by reading the registration; `FINCH_HOOK_TRACE=<path>` makes the hook log each invocation so "ran and allowed" is distinguishable from "never ran". MEMORY.md is Tier 1 only — no pointers, ~500 chars when compacted; consolidate duplicate directives keeping the specific phrasing and both dates. After any write, re-read and grep a unique substring per intended block: a journal's `applied` count is not proof of persistence. **This verification obligation applies to SKILL-file edits too, not only to MEMORY.md** — the 2026-09-30 daily journaled two skill edits as `applied` that were never written to disk. **Run `scripts/finch_write_verify.py` against the `applied` block before a journal is considered writeable** — `python3 scripts/finch_write_verify.py --doc <journal.json> --key applied` exits 0 only when every named artefact exists AND contains the quoted substring, 1 on any failure, and 2 when the claim set is empty or malformed (NOT MEASURED, never a pass). It is also the tool to reach for when re-verifying a PRIOR pass's `applied` claims: the 2026-10-03 pass found one that failed to reproduce and recorded it as ambiguous instead of checking the file. A user "Always"/"Never" is a **priority-0** rule only when it is genuinely system-general: apply immediately, route to MEMORY.md under `## Always Rules`/`## Never Rules`, never batch with lower-priority findings.
